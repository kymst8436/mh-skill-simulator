### F-7 装備の固定・除外(2026-08-24追加)

- **固定**: 部位ごとに防具1つ、生産護石1つを指定できる。固定部位は探索候補がその1択になる。固定護石指定時は護石候補もその1択(護石なし・鑑定護石も使わない)
- **除外**: 防具・生産護石・**装飾品**(2026-08-29追加)を任意数指定できる。候補から外す。除外は候補の優越除去(装飾品は劣候補除去)より先に適用する(除外品に優越されて消えていた候補を復活させるため)
- 装飾品の除外は簡易的な所持数管理を兼ねる: 基本は全所持前提(仕様3.1)のまま、「実は持っていない珠」を検索結果から見つけたら除外して再検索する使い方。除外は装飾品割り当て(3.1手順5)・追加スキル検索(3.5)・装備詳細の代替可能表示(3.1)すべてに効く
- 同一装備の固定と除外は矛盾するため後勝ちで自動解消
- 永続化: AppState.searchFilters(JSON。装飾品はexcludedDecorationsキー。既存JSONにキーが無い場合は空として読む=後方互換)

### F-8 護石ウィッシュリスト(2026-08-25追加)

- 欲しい護石の要求(スキル最大3件+任意のスロット要求)を登録・削除できる
- 手動追加はF-3と同じ規則ベース補助(あり得ない組み合わせは選べない)。最小出現レア度を表示
- 逆引き候補(F-2)からワンタップ登録できる(同一要求の重複登録は不可)
- 項目タップで護石入力(F-3)にプリセットし、保存成功でウィッシュリストから自動削除

## 3. 機能仕様

### 3.1 装備検索(F-1)

#### 目的

欲しいスキルとレベルを指定すると、所持護石の範囲で組める装備一式が提示される。

#### 振る舞い

- スキル条件(スキル+目標レベル、複数指定可)を設定して検索を実行すると、条件を全て満たす「防具5部位+護石+装飾品割り当て」の組み合わせが一覧表示される
- 武器が選択済みなら、武器のスロット・武器スキルを探索に含める
- 武器が未選択なら「何の武器でも良い」とみなし、全武器を候補として自動選択する(優越除去で候補を圧縮。2026-08-24改訂)。カスタム武器(スロット+シリーズ/グループスキルを手動指定)も選択できる(TU追加武器がデータ未収録の間の代替を兼ねる)
- シリーズスキル(2部位/4部位)・グループスキル(3部位)の発動条件を部位数で判定する
- 結果は0件でも即座に返り、0件のときはF-2(逆引き)に接続する

#### 処理順序

```text
1. 検索条件を検証する(スキル重複なし・目標レベルが上限以下)
2. 探索前の枝刈りを行う
   - 条件スキルに寄与しない防具部位・護石・装飾品を候補から除外する
   - 条件にシリーズ/グループスキルが含まれる場合、該当セットの部位を候補に強制的に残す
3. 部位ごとの候補を「条件スキル寄与の上位+スロット構成の優越」で順序付けする
4. 深さ優先で防具5部位+護石を組み合わせ、各ノードで上界チェックを行う
   - 上界チェック: 残り部位の最大寄与+最大スロットでも条件に届かないなら枝を切る
5. 葉に到達したら、不足スキルを装飾品で埋められるか判定する(スロットサイズ降順の貪欲割り当て+失敗時バックトラック)
   - 除外装飾品(F-7)は割り当て候補から外す(劣候補除去より先に適用)
   - 各装飾品を挿した時点で「実際に不足を埋めた分(必要分)」を割り当て結果に記録する(装備詳細の代替可能表示に使う。2026-08-29追加)。必要分が珠の全スキルより少ない複合珠は、必要分を満たす別の珠と交換しても成立が崩れない(装飾品はスキルを足すだけで害がないため)
6. 成立した組み合わせを結果に追加する。上限件数(Q-3: 仮100件)に達したら打ち切り、打ち切りが起きたことを結果に明示する
7. 結果0件なら、F-2の逆引きを自動実行する
```

#### 状態遷移

|現在の状態|イベント|次の状態|副作用|
|---|---|---|---|
|条件編集中|検索実行|検索中|検索条件を最終検索条件として保存|
|検索中|完了(1件以上)|結果表示|なし|
|検索中|完了(0件)|逆引き表示|F-2を実行|
|検索中|キャンセル|条件編集中|途中結果を破棄|

#### エッジケース

|状況|挙動|
|---|---|
|条件スキル0個|検索を実行しない(検索ボタンを無効化。※表現は画面設計)|
|条件1個・低レベル|結果が大量になるため上限件数で打ち切り、打ち切り表示を出す|
|条件が上限超(例: 目標合計が理論上限超)|探索せず即0件→逆引きへ|
|所持護石0個|護石なしで探索する(護石スロットは空として扱う)|
|武器未選択|全武器から自動選択して探索する(結果には採用武器を表示)|
|同一スキルの重複指定|条件検証で弾く(後勝ちで統合)|
|検索中のキャンセル|即座に中断し、条件編集中に戻る|
|検索中のアプリ強制終了|再起動時は条件編集中から開始(途中結果は保存しない)|
|同一条件での連打|実行中は再実行を受け付けない|

#### エラー時の挙動

|エラー|ユーザーに見せるもの|内部処理|
|---|---|---|
|マスタDBが開けない|「データの読み込みに失敗しました。アプリの再インストールをお試しください」|起動時チェックで検出(5.2)。検索は実行不能にする|
|探索がタイムアウト(時間予算超過)|途中までの結果+「条件を絞ると精度が上がります」|ステージ時間予算(検索5秒。2026-08-26)超過で呼び出し側がタスクをキャンセル。エンジンは協調キャンセルで途中結果+打ち切りフラグを返す|

### 3.2 鑑定護石の逆引き(F-2)

#### 目的

検索結果ゼロを「行き止まり」にせず、狙うべき護石というGET目標に変換する。

#### 振る舞い

- 結果0件のとき、「この護石があれば組める」候補が最大N件(Q-4: 仮10件)表示される
- 各候補には、護石のスキル構成・スロット構成・出現するレア度が表示される
- 候補は抽選規則上あり得る護石(全列挙テーブルに存在するもの)に限る
- 護石を1個追加しても組めない場合は「護石では埋まらない」ことを明示する

#### 処理順序

```text
1. 所持護石を除外し「護石スロットを万能ワイルドカード」とした緩和探索を行う
   - 防具5部位+装飾品で到達できる最良状態(各条件スキルの不足レベル・不足スロット)を列挙する
   - 緩和探索でも解が無い場合は 5 へ
2. 各最良状態から「護石に要求される条件」(スキルと最低レベル、必要スロット)を逆算する
3. 要求条件で抽選規則(スキルグループ+パターン)を評価し、あり得る護石候補を生成する
   - 完全一致だけでなく上位互換(要求以上のレベル・スロット)も含める
4. ヒットした護石を「入手しやすさ(レア度昇順)→要求の緩さ」で並べ、上位N件を提示して終了
5. (護石で埋まらない場合)条件スキルを1つ外した場合に組めるかを試行し、
   「外せば組めるスキル」の一覧を代替案として提示する
```

#### 状態遷移

なし(検索結果画面内の表示状態のみ。画面設計で決める)

#### エッジケース

|状況|挙動|
|---|---|
|逆引き候補0件(護石では埋まらない)|処理順序5の代替案(諦め候補スキル)を提示|
|緩和探索でも解なし+全スキル外しても解なし|「条件を見直してください」のみ(理論上ほぼ発生しない)|
|候補が大量(要求が緩い)|レア度昇順で上位N件に絞り、絞ったことを表示|
|所持護石で既に組める条件で逆引きが走る|発生しない(F-1が1件以上返すため)|
|規則テーブルが空/欠損|逆引き機能を無効化し「護石データを更新してください」(5.2の破損検出)|

#### エラー時の挙動

|エラー|ユーザーに見せるもの|内部処理|
|---|---|---|
|逆引きがタイムアウト(時間予算超過)|候補が途中まであれば提示+「探索を打ち切ったため他にも候補がある可能性」注記。候補ゼロなら「時間内に狙える護石を見つけられませんでした」+「時間を延長して再試行」|ステージ時間予算(逆引き4秒。2026-08-26)超過で呼び出し側がタスクをキャンセル。再試行のたびに予算を2倍(上限4倍。探索は決定的で、同じ予算では同じ場所で時間切れになるため)。条件変更・護石追加など入力が変わる再検索では基準予算に戻す。緩和探索・装飾品割り当て・代替提示(手順5)まで全サブ処理が協調キャンセルに従い、結果に網羅フラグ(isExhaustive)を付与して「真のゼロ件」と区別する|

### 3.3 所持護石管理(F-3)

#### 目的

護石入力の苦痛(競合の最大不満点)を、規則データの流用で消す。

#### 振る舞い

- 護石の新規登録では、スキル1を選んだ時点でスキル2・3の候補が抽選規則上あり得るものだけに絞り込まれる
- スキル構成を確定すると、あり得るスロットパターンとレア度が自動候補として提示される
- 生産護石(固定護石)は登録不要(全所持前提で検索対象。Q-6)
- 登録済み護石は一覧・編集・削除できる。削除は確認を挟む

#### 処理順序

```text
1. (新規登録)スキル1の候補 = 規則上スキル1として出現し得る全スキル(パターンのskill1グループの和集合)
2. スキル1選択 → スキル2候補 = スキル1が合致する各パターンのskill2グループの和集合(なし含む。同一スキルは除外)
3. スキル2選択 → スキル3候補も同様に絞り込む
4. スキル構成確定 → 合致するパターンのスロット組み合わせ+レア度の組を候補提示
5. ユーザーがスロット/レア度を選択(候補が1つなら自動選択)
6. 保存
   - ユーザーDBにトランザクションで書き込む
   - 完全一致の登録済み護石があれば重複を警告する(登録自体は許可: 同じ護石を複数所持できるため)
```

#### 状態遷移

|現在の状態|イベント|次の状態|副作用|
|---|---|---|---|
|一覧表示|新規登録開始|入力中|なし|
|入力中|保存|一覧表示|ユーザーDBに書き込み|
|入力中|キャンセル|一覧表示|入力内容を破棄|
|一覧表示|削除実行(確認後)|一覧表示|ユーザーDBから削除|

#### エッジケース

|状況|挙動|
|---|---|
|初回起動(護石0件)|空の一覧+登録への導線(表現は画面設計)|
|想定の100倍(護石1,000件)|一覧・検索とも動作すること(性能予算6.1の対象)|
|規則上あり得ない組み合わせの入力|UI上選択肢に出ないため入力不能(構造的防止)|
|ゲーム側TUで新スキル追加後、手持ちデータが旧規則|旧規則で登録済みの護石はそのまま有効。新規登録はデータ更新後に対応|
|保存中のアプリ強制終了|トランザクションのため未保存として扱われる(次回起動時に不整合なし)|
|削除の連打|1件目の確認ダイアログでモーダル化し多重実行を防ぐ|

#### エラー時の挙動

|エラー|ユーザーに見せるもの|内部処理|
|---|---|---|
|ユーザーDB書き込み失敗(容量不足等)|「保存できませんでした。端末の空き容量をご確認ください」|ロールバック。入力内容は画面に保持|
|ユーザーDB破損検出|「護石データを復元しました(直前の状態)」または初期化の通知|5.2の手順|

### 3.4 データ基盤(F-5)— パイプライン仕様(ビルド時・アプリ外)

#### 目的

配布物に含めるマスタDBを、再現可能な手順で生成する。

#### 処理順序

```text
1. data/source/ のマージ済みJSON(mhdb-wilds-dataスナップショット)を読み込む
2. 検証する
   - 参照整合: 防具・装飾品・護石が参照するskillIdがSkillに存在する
   - 件数が前回生成時から大幅減(>10%)していないか(取得ミス検出)
3. data/charm-rules/ の抽選規則データを読み込み、検証する(グループ参照整合)
4. 規則から鑑定護石を全列挙し、重複を除去して検証用DB(enumerated.db・アプリ非同梱)を生成する
   - 件数・分布をログ出力する(規模の妥当性確認。Q-2)
   - 用途は規則データの検証(実物護石との突き合わせ)と回帰テスト
5. マスタSQLite(bundled.db)を生成し、メタ情報(schemaVersion・生成日・元データのcommit hash)を書き込む
6. 既知の正解ケース(手動で用意した「この条件でこの装備が出る」)で検索エンジンの回帰テストを実行する
```

エッジケース・エラーは開発時ツールのため「検証失敗=ビルド失敗」で停止し、生成物を出さない。

### 3.5 追加スキル検索(F-9)(2026-08-26追加)

#### 目的

検索が成立した後の「まだ何を積めるか」の試行錯誤(スキルを足しては検索し直す往復)を、一覧の一回提示に置き換える。

#### 振る舞い

- 検索結果が1件以上のとき、ユーザー操作で実行する(自動実行しない。Q-13)。0件時は対象外(F-2逆引きの領分)
- 現在の検索入力一式(スキル条件・武器選択/カスタム武器・固定/除外・所持護石)を維持したまま、条件外の各スキルについて「条件に追加しても解が存在する最大レベル」を判定し、一覧提示する
- 一覧の各項目はスキルと最大追加レベル。項目タップでそのスキルを判定済み最大レベルで条件に追加し、F-1を再実行する(検索条件画面の条件にも反映)
- シリーズ/グループスキルも判定対象に含める(Q-14)
- 判定は全スキル確定まで実行する。時間予算による打ち切りは行わない(スキル単位の進捗表示(確定済み数/対象数)があり、待つ/やめるをユーザーが選べるため。2026-08-26決定)。中断はキャンセル(画面離脱)のみ

#### 処理順序

```text
1. 対象スキル集合 = マスタの全スキル − 条件済みスキル
2. 各対象スキルの理論上界レベルを前計算する
   - 候補装備(固定・除外適用後)・武器候補・所持護石・装飾品の最大寄与から、
     F-1の上界チェックと同じ計算で「これ以上は積めない」レベルを求める
   - シリーズ/グループスキルは到達可能な部位数から上界を求める
   - 上界0のスキルは判定せず対象から除外する
3. 対象スキルを理論上界の昇順に並べる
   - 上界が低いスキルほど判定回数が少なく早く確定するため、
     時間切れ時に確定済み件数が最大になる(Q-15)
4. スキルごとに「条件+対象スキルLv l」でF-1の検索(1件見つけた時点で成立)を実行し、最大成立レベルを判定する
   - まず理論上界レベルで成立を試し、成立すればそのまま確定する
     (最頻ケースを1回の探索で済ませ、高価な不成立証明も省略する。2026-08-26実測で採用)
   - 不成立なら l=1 から昇順に判定し、最初に不成立となった l の1つ手前を最大として確定する。
     l=1 で不成立なら追加不可として一覧に含めない
   - 成立レベルの単調性(Lv l が組めるなら Lv l−1 も組める)により、この打ち切りで正しい最大が求まる
   - 武器未指定のときは、対象スキル寄与が最大の武器1本に固定した制限付き探索を先に試す
     (武器固定は探索空間の制限なので成立すれば全体でも成立。不成立のときだけ全武器で確かめる。
      全武器の優越除去がプローブごとに走るのを避ける高速化。2026-08-26実測で採用)
5. 全スキル確定で終了し、一覧を提示する
   - 判定中はスキル1件確定するごとに進捗(確定済み数/対象数)を更新する
   - キャンセル(画面離脱)時は中断し、途中結果を破棄する
6. 項目タップ: 条件に対象スキル(判定済み最大レベル)を追加してF-1を再実行し、条件画面の条件も更新する
```

### 3.6 護石カメラ読み取り(F-10)(2026-08-28追加)

ゲームの装備詳細画面(護石表示)をスマホカメラにかざすだけで、所持護石のスキル構成を入力する。手入力(F-3)の置き換えではなく前段: 読み取り結果は護石入力にプリセットされ、確認・スロット選択・保存はF-3のフローで行う。

#### 方式

- QRスキャン型のライブ読み取り。全フレームへオンデバイスOCR(Vision・ja-JP・精確モード)を実行し、**ガイド枠(各辺25%マージン付き)内のテキストのみ採用**する(処理中フレームはスキップ=直列キュー)。通信なし(6.3のオフライン方針を維持)。VisionのregionOfInterestは使わない(座標変換ズレで見た目の枠と認識領域が食い違い、枠ぴったりに収めると読めない事故が起きたため=2026-08-29実機フィードバック)
- 読み取り対象は**スキル名+レベル+レア度(RARE表記)**。読み取れたレア度はスロット候補の絞り込みに使う。スロットはアイコン表示でOCR不可のため、プリセット後にF-3の規則ベース候補から手動選択(スキル+レア度確定後は通常1〜数択。候補1つなら自動選択)
- 完了判定は3条件の同時成立: (1)護石パネルとしての解釈成立 (2)同一**スキル構成**が連続Nフレーム安定(N=3目安。実機で調整。レア度行は枠位置次第で読めたり読めなかったりするため安定判定に含めず、連続一致中に読めた最新値を採用) (3)抽選規則(CharmRules)上あり得るスキル構成
- 完了時はハプティクスで通知しスキャナを閉じ、護石入力へプリセットする(スキャナから直接保存はしない)

#### 解釈(パース)規則 — Core `CharmScanParser`(プラットフォーム非依存・テスト対象)

|手順|規則|
|---|---|
|正規化|NFKC正規化+空白除去。Lv表記は大文字小文字不問|
|アンカー|護石パネル題名(言語別トークン+bundled.dbの鑑定護石名)を含むテキストと「装備スキル」見出し(言語別表記)を含むテキストが両方枠内にあること(**部分一致**。見出しはアイコン巻き込み誤読「多装備スキル」等が起きるため)。言語別語彙はCore `CharmScanProfile` に集約(2026-08-29改訂。日本語以外の見出し表記は実機未検証)|
|スキル名|マスタDBスキル名と照合。完全一致→曖昧一致(編集距離1以内かつ唯一最小)の順。唯一に絞れなければ不採用(例:「大耐性」は火耐性/水耐性と等距離のため棄却)|
|レベル|正規化後 `lv\d` 完全形のみ。「Lv1/1」(護石レベル行)は形が異なり自然に除外|
|レア度|正規化後 `rare\d` 完全形のみ。確定スキル構成のスロット候補と整合しない値は破棄(nil)|
|対応付け|スキル名とLvトークンを読み取り順(枠内の上→下)で整列し、順序で対応付ける。件数不一致(1〜3件の範囲外含む)は不成立|
|規則検証|対応付け結果の並べ替え(≤3!通り)のうち `CharmRules.candidates` に順に適合する並びを採用。なければ不成立として読み取り継続|

### 3.7 装備比較(F-11)(2026-09-04追加・同日2回改訂)

ツールタブ(F-11系列。モンハンワイルズの便利機能を今後追加していく置き場)の第1弾。

#### 目的

「会心特化と攻撃特化、どちらの装備が強いか」を、**2つのマイセットを並べて、戦闘中の状態(怒り・有効部位・渾身など)とアイテム・食事の効果を切り替えながら**物理期待値で比較できるようにする。候補となる装備は検索→装備詳細→マイセット保存で作っておく(F-6)。本ツールは装備を組み替えない(比較専用)。

#### 振る舞い

1. **ベース装備の選択**: ツールを開くとマイセット一覧(4.15と同じ行)を表示し、ベースとなるマイセットを1つ選ぶ。選ぶと比較画面へ遷移する。マイセットが0件なら空状態(検索→装備詳細→保存への誘導)
2. **比較装備の選択**: 比較画面の右列は最初「＋比較する装備構成を選択」のプレースホルダ。タップでマイセット一覧(sheet)を開き、別のマイセットを選ぶ(ベースと同じものは選べない)。左右どちらの列名タップでも選び直せる
3. **対象装備**: 左右の列に武器・頭・胴・腕・腰・脚・護石をアイコン+名称で縦に並べる。武器の基礎攻撃力・会心率は武器IDでマスタ`Weapon.attackRaw / affinity`を引く。カスタム武器・武器なし・マスタ未収録のときはその列に基礎攻撃力・会心率の手入力行を出す
4. **期待値**: 左右それぞれの会心込み攻撃力(期待値)・攻撃力・会心率・会心倍率を表示し、比較側に差分(比較−ベース、%)を添える。状態・アイテムの変更で即時再計算
5. **状態別(トグル)**: 左右どちらか、または両方の装備が持つ「攻撃・会心に関わる条件付きスキル」(定数表)の和集合を1本の一覧に並べ、行ごとに1つのトグルで**発動中/非発動**を切り替える(左右に分けない。2026-09-04ユーザー決定)。行のラベルはスキル名、発動中はラベルの右隣に「発動中」バッジ。補助行に各装備のレベル「ベース Lv<n> ・ 比較 Lv<n>」(持たない側は「—」)を小さく添える。ONにすると、そのスキルを持つ側の期待値にだけ反映される。条件は戦闘状況(怒り中・有効部位など)なので左右共通の1トグル(片側だけ発動する状況はない)。**両立しない条件**(排他グループ表)も行は分けて表示し、片方をONにしようとしたときに相手がONなら確認アラート「両立しないため<相手のスキル名>がOFFになります」[OK / キャンセル]を出す。OKで自分をON・排他相手をすべてOFFにする(2026-09-04ユーザー決定)。常時発動スキル(攻撃・見切り・超会心)はトグルなしで常に計上し、一覧の先頭に「常時発動」バッジ付きの行として表示する(計上されていることが分かるように。2026-09-04ユーザー決定)
6. **アイテム・食事**: 状態別セクションの末尾に共通(左右両方に効く)の入力を置く。**重複できるもの**はトグル(力の護符 / 鬼人の粉塵)、**重複しないもの**は項目名タップでプルダウン選択(鬼人薬: なし/鬼人薬/鬼人薬グレート、怪力: なし/怪力の種/怪力の丸薬、お食事ムラ気術: なし/【小】/【大】)。選択中はラベル右に「発動中」バッジ。さらに「その他の攻撃力加算 / 会心率加算」の手入力欄を残す(装衣・狩猟笛・効果量非公開スキル・食事スキルの受け皿)
7. 選択中のマイセットID(左右)・トグル・アイテム選択・その他加算はUserDefaultsに保存し復元する
8. 対象は**物理のみ**。属性・状態異常は扱わない。モーション値・肉質・斬れ味・怒り補正は左右共通の係数なので比較に影響しないとみなし含めない(画面に注記)。効果量が確定できないスキル(**千刃竜の闘志**: 記事間で「攻撃力4〜5%」「巧撃加算分×1.04」と表現が揺れる / **パワーストーン**: 採掘した鉱石のレア度・個数で可変、最大+90)は**「未計上」**として該当する側の列に名前だけ表示し、ユーザーが「その他の攻撃力加算」で手入力する(2026-09-04調査で他の効果文非公開スキルは確定=定数表に追加)

#### 計算式(コア `ExpectedAttackCalculator`・プラットフォーム非依存・テスト対象)

```text
乗算 m  = Π(発動中スキルの攻撃倍率)            # 攻撃Lv4/5・火事場力・攻めの守勢・急襲
加算 a  = Σ(発動中スキルの基礎攻撃力加算) + Σ(アイテム・食事の加算) + その他の攻撃力加算
攻撃力 P = floor(基礎攻撃力 × m) + a
会心率 C = clamp(武器会心率 + Σ(発動中スキルの会心率加算) + その他の会心率加算, −100, 100)
会心倍率 K = 超会心倍率[Lv](C ≥ 0) / 0.75(C < 0。負の会心。超会心は無効)
期待値 E = P × (1 + |C|/100 × (K − 1))     # 表示は小数1桁
差分 = (E比較 − Eベース) / Eベース × 100(小数1桁)
```

- 乗算は基礎攻撃力にまとめて掛けて切り捨て、加算はその後(Wildsの表示攻撃力の計算順。**実機のステータス画面と一致することを5.9-6で確認**。ずれたら見直す=Q-19)
- 左右は同じ状態・同じアイテムで計算する(比較の公平性)。装備固有の差はスキルと武器だけ

#### 処理順序

```text
1. マイセット一覧を表示 → ベース選択 → 比較画面へ
2. 各列: EquipmentSet → 武器の基礎攻撃力/会心率(マスタ or 手入力)・activeSkills
3. 左右のactiveSkillsから定数表スキルを抽出 → 条件行(左右のスキル和集合。同じ条件はまとめる)・排他グループの対応表・未計上リストを生成
4. トグル・アイテム・その他加算から、列ごとに P / C / K / E を算出 → 期待値セクション・差分
5. 入力変更のたび4を再実行(同期。数µs)。UserDefaultsへ保存
```

## 4. データモデル

全idはゲーム内部ID(Int32。負値あり)をそのまま使う。実測値: スキル179 / 防具シリーズ194(部位714) / 装飾品361 / 固定護石60系統 / スロットサイズは1〜3 / 部位あたりスロット最大3 / スキル最大Lv7 / 固定護石はスロットなし・スキル最大2。

### 4.1 マスタ(bundled.db・読み取り専用・ビルド時生成)

### 4.2 鑑定護石規則(bundled.db内・ビルド時生成)

**2026-08-22改訂**: 当初は全列挙(EnumeratedCharm)をアプリ同梱とし規則を読まない設計だったが、全列挙の実測が2,076,040件・DB153MBとなりアプリサイズ予算50MB(6.1)を超過したため、**正規化した規則テーブルを同梱し、判定・候補生成は実行時計算**に変更した(決定ログ 2026-08-22)。規則の原本(data/charm-rules/charm-rules.json)の表現形式の変更は、変換パイプラインで吸収してアプリ側に波及させない。

```text
  - lastSearchConditions: JSON文字列 (任意)  # スキルId+目標レベルの配列
  - customWeapon: JSON文字列 (任意)          # カスタム武器設定(v2)
  - searchFilters: JSON文字列 (任意)         # 固定・除外設定(F-7。v3)
```

## 5. 永続化

|項目|決定|
|---|---|
|保存先|マスタ: アプリバンドル内 bundled.db(読み取り専用) / ユーザー: Application Support/MHSimulator/user.db|
|保存形式|両方SQLite。理由: 全列挙テーブルへの索引付き逆引きクエリが必須で、JSONでは都度全読み込みになるため|
|ファイル分割|マスタとユーザーデータを別ファイルに分離(アプリ更新でマスタを丸ごと差し替えてもユーザーデータが無傷)|
|文字コード|UTF-8(SQLite既定)|
|書き込み契機|変更即時(1操作=1トランザクション)。user.dbのみ|
|スキーマバージョン|bundled.db: Meta.schemaVersion(現行=3) / user.db: AppState.schemaVersion(現行=5。移行履歴は4.3参照)|
|移行方針|user.dbのみ移行対象。起動時にschemaVersionを確認し、旧版ならマイグレーション実行。実行前にuser.db.bakを作成|
|破損時の挙動|下記5.2|
|バックアップ|user.dbはiOSの端末バックアップ(iCloud/PC)対象領域に置く。アプリ独自の世代バックアップは持たない(Q-8)|
|二重起動|iOSのため考慮不要|
|エクスポート/インポート|MVPではなし(拡張候補: 所持護石のJSON書き出し)|

### 5.1 書き込み手順(user.db)

```text
1. SQLiteをWALモードで開く(クラッシュ時はWALからの自動リカバリに任せる)
2. 1操作(登録・編集・削除)を1トランザクションで実行する
3. コミット失敗時はロールバックし、UI側に入力内容を保持したままエラー表示する
```

### 5.2 読み込み手順(起動時)

```text
1. bundled.db を開き、integrity_check と Meta.schemaVersion を確認する
   - 失敗: 全機能を読み取り不能状態にし、再インストール案内を表示(バンドル破損は端末側要因)
2. user.db を開き、integrity_check を実行する
   - 失敗: user.db を user.db.corrupt.<日時> に退避し、空のuser.dbを再作成。
     「護石データを初期化しました」を通知する
3. AppState.schemaVersion を確認し、古ければ user.db.bak を作ってから移行する
4. 規則テーブル(CharmPattern)が0件なら逆引き・入力補助を無効化する(3.2エッジケース)
```
