## 1. プロジェクト概要

モンハンワイルズ向けのiOSスキルシミュレータ。**学習型プロジェクト**(データマイニング学習+iOS開発の実践)であり、無料+広告収益・課金なしでApp Storeに公開する(2026-08-23改訂。メイン収益は広告収益)。

差別化の核は**鑑定護石の逆引き**。検索結果ゼロのとき「この護石があれば組める」を、抽選規則上あり得る護石に限って提示する。この機能を持つシミュは現存しない(2026-08-21競合調査)。

技術スタック:

- アプリ: Swift / SwiftUI(iOS 17+、iPhone縦固定)
- データパイプライン: Python(ビルド時実行。アプリには含めない)
- DB: SQLite(素のC APIでアクセス。Q-5解決 2026-08-24)

## 3. データ取得元(JSONデータ)

### 3.1 取得元リポジトリ

**[LartTyler/mhdb-wilds-data](https://github.com/LartTyler/mhdb-wilds-data)** — 非公式Wilds APIの元データ。抽出・マージ済みJSONが `output/merged/` に同梱されている。

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/LartTyler/mhdb-wilds-data.git
cd mhdb-wilds-data
git sparse-checkout set output/merged
```

### 3.2 output/merged/ の内容(2026-08-21取得時の実測)

| ファイル | 内容 | 件数 |
|---|---|---|
| Skill.json | スキル(全レベル効果付き) | 179 |
| Armor.json | 防具シリーズ(pieces配下に部位) | 194シリーズ / 714部位 |
| Accessory.json | 装飾品 | 361 |
| Amulet.json | **護石**(ランク別) | 64系統 |
| Charm.json | 重ね着チャーム(見た目アイテム) | **使わない** |
| Item.json / LargeMonsters.json 等 | アイテム・モンスター | 本アプリでは使わない |
| weapons/*.json | 武器14種+狩猟笛関連 | 武器種ごと(例: GreatSword 90) |

### 3.3 データの重要な性質(ハマりどころ)

- **命名の罠**: 護石は `Charm.json` ではなく `Amulet.json`。Charm.jsonは重ね着用
- 鑑定護石は `Amulet.json` 内の `is_random: true` の4件だが、**`skills: {}` が空**。抽選テーブルは含まれていない(→ §5のcharm-rulesで自作する)
- 全エンティティに `names` / `descriptions` が**15言語**で入っている(`ja`あり)。説明文に `\r\n` が含まれる
- `game_id` はInt32で**負値あり**。そのまま主キーに使う
- アイコンは画像ではなく**メタ情報のみ**(スキル: `icon`種別名+`icon_id` / 装飾品: `icon_color`+`icon_color_id`)。上流リポジトリ・mhdb Wilds APIとも画像アセットは一切持たない(2026-08-24確認)。入手方針は段階導入で決定(2026-08-24): ①MHW_Icons_SVG(MIT)の手描き再現SVG → ②必要になったらWindowsでPAK抽出(REtool系+.tex→PNG)。抽出品使用可(2026-08-23決定)・権利表記画面を用意
- スロットサイズは1〜3。防具は部位あたり最大3スロット。装飾品は `level`=スロットサイズ、`allowed_on` が weapon(295件)/armor(66件)、2スキル持ち複合装飾品が173件
- 固定護石(is_random以外)はスロットを持たず、スキル最大2
- シリーズスキルは `set_bonus`(2/4部位)、グループスキルは `group_bonus`(3部位)としてArmor.json側に入っている。Skill.json側の `kind`(armor/weapon/set/group)と対応
- データは**2026-04時点**のスナップショット。以降のタイトルアップデート分は含まれない可能性がある(仕様Q-10: 追随はアプリ更新同梱)

### 3.4 ライセンス・クレジット(仕様Q-11・未確定)

## 4. 最初の作業: データパイプライン(アプリ実装より先)

**アプリのXcodeプロジェクトを作る前に、データパイプラインを完成させる。**アプリはbundled.dbが無いと1画面も成立しない。手順は `仕様.md` 3.4(F-5)に準拠。

```text
リポジトリ構成(企画書§8より。data/とtools/を先に作る)

MHSimulator/  (= 本リポジトリ mh-skill-simulator)
├─ Docs/                   # 本書・企画書・仕様
├─ data/
│  ├─ source/              # mhdb-wilds-dataのスナップショット(取得commit hashを記録)
│  ├─ charm-rules/         # 鑑定護石の抽選規則(自作データ。§5)
│  └─ generated/           # bundled.db ほか生成物(gitignore対象か要判断)
├─ tools/
│  ├─ convert/             # JSON→SQLite変換(Python)
│  └─ enumerate-charms/    # 規則→あり得る護石の全列挙(Python)
└─ app/                    # Xcodeプロジェクト(Phase 3以降)
```

作業順:

1. **取得スクリプト**: mhdb-wilds-dataをsparse cloneし、`output/merged/` を `data/source/` にコピー。取得時のcommit hashを `data/source/SOURCE.md` に記録
2. **変換スクリプト(tools/convert)**: 仕様.md 4.1のスキーマでbundled.dbを生成。参照整合チェック(skillId存在確認)と件数検証(前回比>10%減で失敗)を含める
3. **検証**: 件数が§3.2の実測値と一致することをテストで固定(スキル179・部位714・装飾品361)
4. **charm-rules(§5)→全列挙(tools/enumerate-charms)**: EnumeratedCharmテーブルを生成し件数・分布をログ出力
5. ここまでできたらPhase 2(UIなし検索エンジン+単体テスト)へ。UI(Phase 3)はその後

## 5. 鑑定護石の抽選規則データ(最重要・要注意)

逆引き機能の生命線。**仕様Q-1(優先度S)**。

- 一次ソース: [Nettoge — 鑑定護石の出現パターンとシミュレータ](https://nettoge.com/mhwilds-talisman-patterns-simulator/)(海外コミュニティのゲームデータ解析を日本語でまとめたもの)
- 構造の概要: スキルは「スキルグループ」に分類され、レア度(5〜8)ごとに選べるグループが決まり、スキル1のグループ選択に応じてスキル2・3のグループが階層的に決まる。スロットパターンもレア度ごとに固定(例: レア8は武器スロ①必須+防具スロ数パターン)。**確率は取り込まない**(検索の正しさに不要。決定済み)
- `data/charm-rules/` にこの規則を機械可読データとして写経する。**規則を推測で補完・捏造しないこと。**出典ページで確認できない部分は「不明」としてユーザーに確認する
- 検証: ユーザーが実際に入手した鑑定護石と突き合わせ、「列挙に存在しない実物」が出たら即報告(規則データの誤り)。この検証が済むまで、逆引き機能は「実験的機能」扱いとする
- アプリは正規化された規則テーブル(CharmSkillGroup/CharmPattern)を参照して実行時計算する(仕様4.2、2026-08-22改訂。全列挙同梱は153MBで予算超過のため断念。規則原本の形式変更は変換パイプラインで吸収)。全列挙はenumerated.db(アプリ非同梱)として検証・回帰テスト用に残す

## 6. 実装上の決定済み事項(要約)

詳細と理由は仕様.md 8章と決定ログを参照。

- マスタ(bundled.db・読み取り専用)とユーザーデータ(user.db)は**別SQLite**。アプリ更新でマスタを差し替えてもuser.dbは無傷
- 検索(F-1): 枝刈り付き深さ優先+装飾品貪欲割り当て。上位100件打ち切り(仮)。性能予算: 条件5スキル+護石100個で3秒以内
- 逆引き(F-2): 護石ワイルドカード緩和探索→不足分逆算→規則評価で候補生成。護石で埋まらなければ「外せば組めるスキル」を代替提示
- 護石入力補助(F-3): 規則評価(パターン×グループ照合)でスキル2・3候補を絞る(あり得ない護石は入力不能)
- 固定護石は最終ランク全所持前提で検索対象 / 防御力はmax基準 / 武器は固定選択(探索変数にしない)
- user.dbはWALモード・1操作1トランザクション。起動時integrity_check、破損時は退避→再作成→通知

## 7. してはいけないこと(2026-08-23改訂)

- 音声・3Dモデル等の大型ゲームアセットの同梱(**アイコン類の抽出品は使用可**。著作権がカプコンにある旨の権利表記画面を別途用意する。2026-08-23決定)
- アプリ名・Store掲載文での「モンハン」「Monster Hunter」「Wilds」の正面使用(「MH」略称は可。非公式である旨を明記)
- 課金・テレメトリ・解析SDKの追加(**広告は可**。メイン収益は広告収益とする。2026-08-23決定。広告SDKに伴う通信・プライバシー申告は許容し、コア機能はオフライン完結を維持)
- 非公式APIへの実行時アクセス(データはビルド時同梱のみ)

※広告収益化と抽出アセット使用の併用は権利リスクを高める組み合わせであることを認識した上での決定。申し立て時の即時取り下げ方針は維持
- ダメージ計算・攻略情報など企画書「やらないこと」領域への善意の作り込み
- 抽選規則の推測補完(§5)
